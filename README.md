## Project Overview

ARCHIVE is a web-based social networking platform inspired by Meta Threads, Facebook, and Instagram.

The project was built to apply core web development knowledge in a practical product, including:

* MVC architecture
* User authentication and authorization
* Relational database design
* Social interaction features
* Media upload handling
* AJAX-based user interactions
* Responsive user interface
* Admin dashboard and moderation system
* Deployment on a cloud platform

ARCHIVE allows users to create posts, upload images or videos, like and comment on posts, follow other users, search for users and hashtags, receive notifications, and report inappropriate content.

The system also includes an admin dashboard for managing users, moderating reported content, sending system notifications, and viewing platform statistics.

---

## Business Understanding

Modern social networks are not only communication platforms but also digital spaces where users express themselves, build communities, and interact with people who share similar interests.

ARCHIVE was developed as a miniature social networking system to simulate how a real social platform works. The project focuses on two main goals:

1. Build a user-friendly social networking experience.
2. Provide administrators with tools to manage users, moderate content, and monitor system activity.

The project also addresses the need for healthy online community management through reporting, moderation, account control, and system notification features.

## System Architecture

ARCHIVE follows the MVC architectural pattern.

```text
User Request
     |
     v
Public/index.php
     |
     v
Controller
     |
     v
Model <----> MySQL Database
     |
     v
View
     |
     v
User Interface
```

### MVC Responsibilities

| Layer      | Responsibility                                            |
| ---------- | --------------------------------------------------------- |
| Model      | Handles database queries and data logic                   |
| View       | Displays user interface                                   |
| Controller | Receives requests, processes logic, and returns responses |

The system uses centralized routing through `Public/index.php`, session-based authentication, and role-based access control for admin features.

## Database Design

The database is designed to support user accounts, social interactions, content management, notifications, reporting, and moderation.

### Main Tables

| Table                   | Purpose                         |
| ----------------------- | ------------------------------- |
| `users`                 | Stores user account information |
| `roles`                 | Stores user roles               |
| `posts`                 | Stores post content             |
| `postimages`            | Stores uploaded media paths     |
| `comments`              | Stores comments and replies     |
| `likes`                 | Stores post likes               |
| `follows`               | Stores follow relationships     |
| `hashtags`              | Stores hashtags                 |
| `posthashtags`          | Links posts with hashtags       |
| `notifications`         | Stores user notifications       |
| `notificationtypes`     | Stores notification categories  |
| `reports`               | Stores user reports             |
| `search_history`        | Stores search history           |
| `userblocks`            | Stores blocked users            |
| `password_reset_tokens` | Stores password reset tokens    |
| `adminlogs`             | Stores admin activities         |

## Installation and Setup

### Prerequisites

Make sure the following tools are installed:

* PHP 8.0 or higher
* MySQL 8.0 or higher
* Composer
* Git
* XAMPP or another local PHP/MySQL environment

---

### 1. Clone the Repository

```bash
git clone https://github.com/ptudw-n07-archive/PTUDW-N07-Social-network.git
cd PTUDW-N07-Social-network
```

---

### 2. Install Dependencies

```bash
php composer.phar install
```

---

### 3. Configure Environment Variables

Copy the environment example file:

```bash
cp .env.example .env
```

Update the `.env` file:

```env
APP_URL=http://localhost:8080
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=db_archive
DB_USER=root
DB_PASSWORD=
DB_SOCKET=
UPLOADS_ROOT=Public/uploads
```

> `UPLOADS_ROOT` should be set to `Public/uploads` for local development so uploaded media can be displayed correctly.

---

### 4. Create and Import Database

Create the database:

```bash
mysql -u root -e "CREATE DATABASE IF NOT EXISTS db_archive CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
```

Import the provided SQL file:

```bash
mysql -u root db_archive < db_archive_final.sql
```

---

### 5. Run the Application

Using PHP built-in server:

```bash
php -S 0.0.0.0:8080 -t . Public/index.php
```

Open the application:

```text
http://localhost:8080
```

---

## Google OAuth Setup

To enable Google Login:

1. Go to Google Cloud Console.
2. Create an OAuth Client ID for a Web Application.
3. Add the authorized redirect URI:

```text
http://localhost:8080/App/Controllers/GoogleLoginController.php
```

4. Add the following values to `.env`:

```env
GOOGLE_LOGIN_CLIENT_ID=your-client-id
GOOGLE_LOGIN_CLIENT_SECRET=your-client-secret
GOOGLE_LOGIN_REDIRECT_URI=http://localhost:8080/App/Controllers/GoogleLoginController.php
```

## Deployment

ARCHIVE is prepared for deployment on Railway.

### Required Railway Environment Variables

```env
APP_URL=https://your-railway-domain
DB_HOST=your-db-host
DB_PORT=3306
DB_NAME=your-db-name
DB_USER=your-db-user
DB_PASSWORD=your-db-password
UPLOADS_ROOT=/data/uploads
```

### Start Command

```bash
sh ./run-app.sh
```

### Health Check

```text
/Public/health.php
```

### Upload Storage Note

For persistent file uploads on Railway, a volume should be mounted to:

```text
/data/uploads
```

The runtime script creates a symbolic link:

```text
Public/uploads -> UPLOADS_ROOT
```
